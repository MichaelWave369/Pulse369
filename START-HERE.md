## Start locally on Windows, macOS, or Linux

1. Extract the ZIP and open a terminal inside `Pulse-369`.
2. Install Node.js 22.13 or newer and pnpm 11.25.0, the version declared by this project. Installing dependencies requires internet access.
3. Run these commands in order:

```sh
pnpm install --frozen-lockfile
pnpm exec wrangler d1 migrations apply DB --config wrangler.local.json --local
pnpm run dev
```

Open `http://localhost:5173`, or the URL printed by the terminal. Click **Sign in** to use the included localhost development account. This is a development simulation, separate from your hosted account. It uses an empty local database and local audio storage.

The database command initializes only the local D1 emulator. Its placeholder database ID does not provision, connect to, or publish a production service. Local runtime data is created under `.wrangler/`; keep that folder to preserve local progress.

Choose **Start session** for desktop practice. A/S hit purple targets; K/L hit lime targets. Space or Escape pauses. Read `README.md` for the full controls and feature guide.

## Build and verify

```sh
pnpm run build
node node_modules/typescript/bin/tsc --noEmit --incremental false
node scripts/verify-game.mjs
node scripts/verify-studio.mjs
```

The tests use temporary identities, databases, and buckets. The included v5 program previously passed 81 game/sensor checks and 130 Worker integration checks. Headset rendering, physical Bluetooth monitors, comfort, and real network audio drift still need device testing.

The included `dist/` is a full Worker/browser build, not a standalone HTML page. It still needs the database, bucket, and identity integration described below. Local development supplies the localhost sign-in simulation; directly serving the production Worker does not add that simulation.

## Hosting and VR

Pulse 369 is a browser/WebXR application, not a Windows executable, Unity project, or Android/Quest APK. Double-clicking a file from the ZIP does not start the app.

Hosted saved progress, clans, rooms, chat, and uploads need a Cloudflare-compatible Worker with D1 binding `DB`, R2 binding `BUCKET`, and all five migrations applied. HTTPS is needed for headset VR and Bluetooth, and browser/device support varies.

Hosted sign-in uses the Sites platform's trusted identity headers. Self-hosting elsewhere requires an authenticated gateway or replacement authentication integration. User-supplied identity headers alone do not provide account security. The localhost sign-in is for local testing only.

The source retains the original hosting manifest for restoration. Compiled Wrangler configuration uses placeholder storage IDs; configure actual bindings before deployment. No hosting secrets are included. No cloud language-model service is configured: coaches and partners use local game AI.
